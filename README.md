# Voice Router / Saqta Insurance

Демонстрационный контакт-центр для кейса HackAlem **Voice Router**. Пользователь обращается текстом или голосом; LLM выбирает сценарий из официального каталога, сервер применяет политику уверенности, формирует ответ по базе знаний и возвращает трассировку для supervisor. Saqta Insurance и данные клиентов вымышлены.

**Рабочая backend-сборка: `tim/backend`. Интерфейс по референсам: `danil/frontend`.** Это рабочие ветки, не завершённый релиз в `main`. Для функционального показа без React в backend есть встроенная страница жюри.

## 1. Что требовалось на хакатоне

Основание: [зафиксированные требования кейса](docs/HACKATHON_REQUIREMENTS.md) и [README официального starter kit](starter-kit/README.ru.md).

Нужно построить **голосового ИИ-бота с веб-интерфейсом**, в котором содержательное решение о сценарии принимает LLM, а не классический intent-классификатор. Жюри должно говорить в микрофон, получать голосовой ответ и видеть после каждой реплики transcript, выбранный сценарий, краткое объяснение, альтернативы и время стадий. Нужны русский, казахский, смешанная речь, контекст до 10 ходов, смена темы и различение близких сценариев.

**Текст является дополнительным каналом. Проверенный текстовый чат не означает, что обязательный голосовой кейс уже закрыт.** Главный результат: правильная маршрутизация естественных обращений. STT превращает речь в текст, router выбирает сценарий, TTS озвучивает ответ; это разные функции.

В исходном наборе 40 бизнес-сценариев, 3 системных намерения и 104 размеченные реплики для локальной оценки. Например, запрос статуса выплаты и несогласие с суммой относятся к разным сценариям. Жюри использует скрытые реплики; labels, ID и исходные данные не меняются ради метрик. Нельзя подменять живую работу фикстурами или записанным сценарием. Используются только синтетические данные; необратимые действия без подтверждения запрещены.

Уточнение, handoff, возврат к прерванной теме, streaming и оптимизация задержек описаны в требованиях и starter kit отдельно от основной голосовой цепочки. Не следует обещать полный операционный backend страховой компании вместо фактически реализованного объёма.

## 3. Быстрый запуск для жюри

Нужны Python 3.10+, доступ к приватному репозиторию и интернет для установки пакетов и работы OpenAI. Встроенная страница не требует Node/React.

### Новый клон: Windows / PowerShell

```powershell
git clone --branch tim/backend https://github.com/BAITC-Hacks/hack-dcb251c0-agroalem.git voice-router
cd voice-router
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
notepad .env.local
```

В `.env.local` задайте новый разрешённый `OPENAI_API_KEY`. Существующий файл не перезаписывайте. Затем:

```powershell
py run_mvp.py
```

Launcher создаёт `.venv`, устанавливает `backend/requirements.txt` и запускает сервер. Встроенная страница: **http://127.0.0.1:8000**. API-документация: **http://127.0.0.1:8000/docs**. Остановка: `Ctrl+C`.

### Linux / macOS

```bash
test -f .env.local || cp .env.example .env.local
# Заполните локальный ключ, затем:
python3 run_mvp.py
```

С уже установленными зависимостями: `.venv\Scripts\python.exe run_mvp.py --no-install` на Windows или `.venv/bin/python run_mvp.py --no-install` на Linux/macOS. Пропуск установки **не включает offline-модели**.

В рабочей папке с незакоммиченными изменениями сначала изучите `git status`. Не используйте `reset --hard`, принудительный push или удаление файлов ради переключения ветки.

### React-интерфейс Данила

В его рабочей ветке при работающем локальном backend на порту 8000:

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Страница **http://127.0.0.1:5173**, запросы идут через Vite proxy `/api` на локальный backend. **127.0.0.1 всегда относится к компьютеру, на котором открыт браузер/запущен proxy.** Это не ссылка на компьютер второго участника. Для проверки используйте отдельный backend checkout на том же ПК; не сливайте весь `tim/backend` в frontend ради запуска или чтения контракта. Финальное объединение выполняет Tim после приёмки.

## 4. Как пользоваться

**Текст:** введите вопрос, отправьте, откройте trace нужной реплики. Ошибка нового запроса не получает старый успешный trace.

**Встроенный голос:** «Записать голос» → разрешить микрофон → «Остановить и отправить». Запись ограничена 60 секундами. Ответ можно прослушать в плеере; голос обозначен как созданный ИИ. Также доступна загрузка файла.

**Файлы:** WebM, MP4/M4A, MP3, WAV до 20 MiB; пустые/неподдерживаемые файлы отклоняются. React-кнопки должны опираться на тот же контракт и доступный браузеру MIME, не угадывать формат.

**Ошибка TTS:** текст и trace остаются. Повторяется только озвучка, не вся реплика. **Отмена:** прекращает ожидание браузера, но не гарантирует отмену уже принятого сервером/API запроса. Автоматического повторения нет.

**Новая сессия:** новый ID и чистая браузерная история. Перезапуск сервера сбрасывает память. Backend не является постоянной БД и не рассчитан на публичный multi-worker production.

### Живой показ, а не заготовленные ответы

1. Спросить адрес офиса, затем время его работы; проверить сценарий, grounded-ответ и историю.
2. Проверить русский, казахский и смешанный ввод на новых фразах; сверить транскрипт и routing.
3. Запросить оператора: проверить handoff без заявления о реальном соединении.
4. Произнести запрос в микрофон и прослушать ответ; отказать в разрешении и убедиться, что текст остаётся доступен.
5. Проверить настоящий неуспешный запрос: без выдуманного ответа/тайминга и без чужого trace.

Корректность проверяется фактическим прогоном. Записанный ролик или fixture не заменяет приёмку.

## 5. API и настройки

Полный источник: [.codex/INTEGRATION_CONTRACT.md](.codex/INTEGRATION_CONTRACT.md).

| Метод | Endpoint | Запрос / ответ |
| --- | --- | --- |
| GET | `/health` | Каталог и наличие настройки; не проверка ключа вызовом OpenAI. |
| GET | `/v1/config` | Публичные параметры/форматы, без секретов. |
| POST | `/v1/turn/text` | JSON `{session_id,text}`; текстовый ответ и trace. |
| POST | `/v1/audio/transcriptions` | Multipart `file`; `{text,latency_ms}`, без создания хода. |
| POST | `/v1/audio/speech` | JSON `{text}` до 2000 символов; binary MP3 `audio/mpeg`. |
| POST | `/v1/turn/audio` | Multipart `session_id`, `file`, `include_audio`; тот же текстовый путь и необязательная озвучка. |

Аудиоответ: `assistant_audio: {mime_type,base64,ai_generated}` или `null`, плюс `audio_error`. При неудачной TTS после успешного текста HTTP 200 сохраняет текст/trace. Сценарии под уточнением являются кандидатами, не выполненными операциями. `confidence` не является откалиброванной вероятностью.

Поддерживаемые MIME-базы: `audio/webm`, `video/webm`, `audio/mp4`, `video/mp4`, `audio/x-m4a`, `audio/mpeg`, `audio/mp3`, `audio/mpga`, `audio/wav`, `audio/x-wav`. Параметры вроде `codecs=opus` допустимы для разрешённой базы; Ogg не заявляется.

Ошибка: 413 размер, 415 формат, 422 ввод, 429 ёмкость сессий, 503 настройка/доступ, 502 провайдер/схема/сеть/квота, 504 timeout. Полная пакетная генерация озвучки может измеряться в `tts`; `tts_first_audio=null`, поскольку первое услышанное пользователем аудио не измеряется. `total` не является latency от конца речи до первого звука.

| Переменная | Default / назначение |
| --- | --- |
| `OPENAI_API_KEY` | Только локальный серверный секрет. |
| `OPENAI_ROUTER_MODEL` | `gpt-4.1-mini` |
| `OPENAI_RESPONSE_MODEL` | `gpt-4.1-mini` |
| `OPENAI_STT_MODEL` | `gpt-4o-mini-transcribe` |
| `OPENAI_TTS_MODEL` | `gpt-4o-mini-tts` |
| `OPENAI_TTS_VOICE` | `coral` |
| `OPENAI_TIMEOUT_SECONDS` | `45` на запрос провайдера. |
| `CORS_ORIGINS` | Локальные origin Vite на 5173. |

Приоритет: окружение процесса → `.env.local` → `.env`. Старое явно заданное имя модели перекрывает default. Runtime использует OpenAI REST через HTTPX; **NVIDIA-провайдер и локальные модели не подключены**. Исследование альтернатив не меняет runtime автоматически.

## 6. HackAlem Sandbox, сеть и ключи

По переданной организаторами инструкции, HackAlem Sandbox выбирается как workspace ChatGPT/Codex. Для приложения отдельно принимается приглашение в API Platform, выбираются организация хакатона и командный проект и создаётся разрешённый проектный ключ. Членство, доступные модели и квоты этого проекта здесь не проверены.

**Это доступ к сервисам, не установка моделей на ПК.** Вход в Codex не заполняет `.env.local`. Backend отправляет запросы на `https://api.openai.com/v1/`, поэтому живые LLM/STT/TTS требуют сети. После установки зависимостей офлайн возможны редактирование кода и тесты с fixtures, но не новая маршрутизация облачной моделью. Полностью автономный inference не реализован.

Если ключ опубликован или передан в общий чат, отзовите его и создайте новый в проекте команды. Не копируйте секрет в README, Git, PR, screenshot, `.env.example`, `VITE_*`, `NEXT_PUBLIC_*` или браузер. Новый ключ сохраняет локально владелец backend. Эта документация не выполняет вход в workspace, установку ключа или проверку баланса.

## 7. Последний интеграционный срез

**Tim:** актуальный backend, полный pytest, живые RU/KK/mixed smoke, 104 predictions и официальный evaluator; фактические результаты в TIM_STATE. Tuning только после baseline.

```powershell
py run_mvp.py --check
.venv\Scripts\python.exe -m backend.scripts.run_baseline
```

Baseline сохраняет модель, Git SHA, SHA-256 датасета и результаты scorer. При сбое остаётся partial checkpoint. Неполный прогон не считается baseline; API-запросы расходуют проектную квоту.

**Danil:** сохранить проверенную вёрстку, прочитать свежий аудиоконтракт, подключить запись и MP3 playback к уже опубликованному `AudioApiClient`, проверить новую пару backend/frontend и обновить собственный state. Не ждать повторного выбора архитектуры; не менять provider/routing ради кнопок. Точный исполняемый бриф: [prompts/DANIL_VOICE_FINISH.md](prompts/DANIL_VOICE_FINISH.md) на `origin/tim/backend`.

Формат приёмочного отчёта: оба SHA, команда, среда, результат тестов и реального запроса. Не публиковать ключи и личные данные. Каждый законченный срез: проверка → state/handoff → целевой commit → push своей ветки. Push не равен merge. PR #2 имеет конфликты, PR #3 допускает merge; оба draft на момент сверки. История не переписывается; окончательное слияние и проверка свежего клона отдельно.

## 8. Ограничения

Это read-only консультация и маршрутизация, не исполнение страховых операций. Нет выпуска/изменения/расторжения полиса, регистрации убытка, SMS, записи к врачу, реального оператора, полного confirmation executor, постоянной БД, авторизации, streaming и доказанного latency SLA. Grounding-промпт не гарантирует правильность любого ответа. Качество казахской речи и смешанного ввода нужно измерять, а не выводить из наличия поля `kk`.

Дата среза синтетических данных **2026-10-01** применяется внутри датасета, а не заменяет календарную дату. Сведения Saqta не являются реальными страховыми или юридическими рекомендациями.

При 503/502/504 проверяйте локальный ключ, API-проект, модель, квоту и сеть. При проблеме микрофона используйте localhost/HTTPS и разрешения; остаются текст/файл. Без полного клона `starter-kit` приложение не воспроизводится. `mergeable=true`, зелёный fixture-тест и `/health` сами по себе не означают завершённую приёмку.
